# Domain docs

This repository uses a single-context layout: root `CONTEXT.md` for domain vocabulary and `docs/adr/` for architectural decisions.

## Before exploring

Read `CONTEXT.md`, then any ADRs in `docs/adr/` relevant to the area being changed. Proceed silently when a file or directory is absent. Domain-modeling workflows create documentation as terms and decisions are resolved.

## Vocabulary and decisions

Use the glossary's terms in issue titles, refactor proposals, hypotheses, and tests. If a needed concept is missing, reconsider whether it belongs to the domain or record the gap for domain modeling.

If a proposal contradicts an existing ADR, identify the ADR and explain why its decision should be reconsidered.
